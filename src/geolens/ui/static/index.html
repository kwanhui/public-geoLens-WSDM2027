Compare the geolocation engines on a post, on an account's recent posts, or on both.

Each engine names one place from a closed candidate list. Post-level engines read the post on its own, and user-level engines read the account's recent posts. The verification flag reports when the two point far apart.
Data handling

Posts and timelines are not stored by GeoLens.

With the LLM engines selected, the post and the timeline are sent to OpenAI and Anthropic, which retain API inputs under their own policies.

An onboarded place's name, region hint and drafted profile are stored on this instance, listed to every visitor until they expire, and included in later LLM prompts. Onboard only names that can be public.

The per-address limits process your IP address for the hour they count over.

Map tiles are requested from openstreetmap.org by your browser, including under "Local engines only", and indicate roughly where a result is.

In a bulk run, row ids should not be account identifiers.

Do not submit data about identifiable people without a lawful basis. The verification flag is a prompt for review, not evidence.

Cold-start Place Onboarding

Add a place that the catalogue lacks, from its name and its country or region.

The candidate list is closed, so no engine can predict a place that the catalogue does not hold. To add one, you type only its name and its country or region. A drafting model, GPT-4o-mini, then writes a short profile of the place, with aliases, landmarks, local foods, slang, a note and an approximate coordinate. The country or region tells the model which place of that name is meant, and the panel warns when the drafted coordinate falls outside that country.Once onboarded, the place is one more candidate that every engine can pick, and no engine is retrained. The gazetteer matches the name, the aliases and the landmarks in a text. ContrastGeo compares the text with the place name, FewUser with a short phrase around the name, and RetrieveZero with a passage built from the profile. The prompted LLM engines read the name in the candidate list of their prompt.The coordinate pins the place on the map and enters the distance measures, so an approximate point is enough for a town or an estate. Onboard adds the place to the catalogue at once, with the drafted profile, and Save and use replaces that draft with your corrections. Without an API key, the draft comes from an offline placeholder and every field needs correcting.

    Verification flag

    A prompt for review, not a finding.

    Most often one of the two predictions is wrong. What the candidate causes mean, and which places are compared, is below.
    What the candidate causes mean, and which places are compared
    • One of the two predictions is wrong. Both levels answer from the same closed catalogue, and each is right about half the time, so two wrong answers land far apart more often than a real move does. This is the most common cause.
    • The post is about another place. The post-level engines read what a post is about, not where it was sent from. An account writing from abroad about a flood at home is the case this misreads most often.
    • Travel post. The account holder is visiting a different place from where they normally post.
    • Shared or compromised account.
    • Misleading geotag. The post claims a place it is not from.

    Four things are worth checking. The posting times against local time in each place, a reverse image search on any media, the account's age and posting history, and whether unrelated accounts report the same event from the same place.

    GeoLens reads only the text of the post and of the timeline, and no images, metadata, timestamps, account age or network.

    The flag compares the consensus place of each level, that is, every engine's top prediction weighted by its confidence. The fused prediction shown below is a different quantity, the sum of each engine's top-k scores (or reciprocal rank fusion), so the two can name different places for the same level. For the same reason, the flag does not depend on the fusion method selected in the input panel.

      How the fused prediction is computed

      Fused prediction: the sum of each engine's top-k scores, or reciprocal rank fusion when that is selected. The verification flag compares a different quantity, the per-level consensus, which is each engine's top prediction weighted by its confidence, so the two can name different cities. Engine scores are not calibrated probabilities. An LLM confidence is self-reported, and an encoder score is a softmaxed cosine similarity.
